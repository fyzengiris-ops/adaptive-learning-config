# 增量变更范围模式（通用）

本文件是 **后置 / 局部需求优化** 的通用规范，可随 `.ai/skills` 整夹复制到任意项目。  
不绑定具体业务域名、页面名称或技术栈。

配合阅读：

```txt
.ai/skills/shared/project-context.md
```

---

## 1. 适用场景

| 模式 | 何时用 |
| --- | --- |
| **全页模式** | 新页面、大重构、首次为整页建立业务逻辑 |
| **增量模式** | 已有页面上做部分需求调整；只审、只写本次相关逻辑 |

用户出现以下表述时，**默认启用增量模式**（除非用户明确要求全页审核）：

- 「本次只改 / 只调整…」
- 「局部优化 / 后置补需求」
- 「不要整页重审 / 只写改动部分的 PRD」
- 已提供变更说明、diff、或明确的变更能力列表

---

## 2. 三类对象（核心）

增量模式下，范围清单必须按三类标注，**禁止**「只列直接改动的控件、其余一律跳过」。

| 类型 | 代号 | 含义 | Skill0 处置 |
| --- | --- | --- | --- |
| 直接变更 | **A** | 本次明确新增、修改、下线或替换的对象 | **必审** |
| 连带影响 | **B** | 控件/文案可能未改，但因 A 导致读写、校验、保存、导入导出、状态、权限、回显等规则变化 | **必审** |
| 无影响 | **C** | 与 A 无数据、流程、展示、校验耦合 | **可跳过** |

**必审集合 = A ∪ B。**  
Skill1 只对必审出决策题；Skill2/5 只为必审写/更新业务逻辑与 PRD。  
对 C：不重审、不改写已有业务逻辑、不整页重写无关 PRD 章节。

---

## 3. 连带影响发现规则（通用）

对每个 **A** 类对象，必须追问并尽量列入 **B**（有则列，无则在备注写「已排查无连带」）：

1. **谁展示它？**（只读回显、列表标签、详情卡片、聚合区）
2. **谁编辑 / 清空它？**（表单项、弹窗、批量操作）
3. **谁在保存 / 提交 / 发布时带上它？**（页面级保存、完成编辑、发布确认）
4. **谁校验它？**（必填、格式、角色权限、前后端校验）
5. **谁导入 / 导出 / 同步它？**（模板列、说明文案、校验结果）
6. **谁在状态 / 变更记录 / 权限上受它影响？**（待发布维度、历史、角色可见性）

典型 **B** 例（说明用，不要当业务清单）：

- 页面新增字段 → **保存 / 取消 / 完成编辑** 虽未改按钮 UI，仍可能需重审
- 新增列表列 → **导出模板说明、导入校验** 可能需重审
- 改数据结构 → **空态、未设置态、变更计数** 可能需重审

**禁止**：在未做上述连带分析时，把「本页其他按钮/区域」批量标为可跳过。

---

## 4. 与全页模式的关系

- 全页模式：仍可使用「必审 / 可跳过 / 待你定」，但不强制 A/B/C 三列；可按整页扫描。
- 增量模式：输出清单时必须带 **影响类型（A/B/C）**；C 可合并为一行「其余未受影响区域」并写清原因，但 **B 必须逐条列出**，不可吞进「其余」。

---

## 5. 落盘与下游约束

增量模式确认后的清单文件须包含：

- 审核模式：`增量`
- 本次变更摘要（用户原话或复述）
- A / B 必审列表（含影响类型）
- C 可跳过列表或「其余无影响」说明
- 约束句：`仅对 A∪B 审核与编写业务逻辑；不对 C 重审或改写既有口径`

Skill1 / Skill2 / Skill5 读取到「审核模式：增量」时，必须遵守本文件第 2、3、5 节。

---

## 6. 旧整页 PRD 模板

若项目中存在历史「整页 PRD 编写模板」（非本 `.ai` 产出），**默认不作为**本流程的写作或审核规范，除非用户当轮明确要求沿用。  
业务逻辑与 PRD 以本套 Skill 的决策记录、`logicSections`、增量/全页 PRD 输出为准。
