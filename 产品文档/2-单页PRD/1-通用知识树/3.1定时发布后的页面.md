# 3.2 定时发布后的页面【GPT更新】

# 页面目标
用于在用户已设置定时发布后，在详情页顶部持续提示当前定时发布状态，并支持用户取消定时发布。  
同时，在定时发布尚未执行前，若用户再次进入编辑并产生新的变更，页面顶部状态需从【定时发布中】切换为【待发布】，引导用户重新确认发布内容。

# 所属页面
知识体系管理 > 通用知识树 > 详情页 > 定时发布后的页面

# 页面区域

## A. 顶部状态提醒区
位于详情页顶部，用于展示当前知识树的发布状态提醒，包括定时发布中状态和待发布状态。

## B. 详情内容区
用于展示当前知识树的基础信息、知识点树结构及右侧详情内容。

# 组件说明

## A. 顶部状态提醒区组件

### A1. 蓝色定时发布提醒条
用于在已设置定时发布且当前未产生新的待发布变更时展示。
- 状态图标：时钟图标
- 状态文案：显示版本号、定时发布时间及自动发布说明
- 取消定时按钮：点击后取消当前定时发布任务

### A2. 橙色待发布提醒条
用于在已存在定时发布任务的基础上，用户再次编辑并产生新的待发布变更后展示。
- 状态图标：警示图标
- 待发布数量：显示本次待发布变更数量
- 状态文案：提示当前存在新的待发布内容，尚未重新确认发布
- 发布按钮：点击后打开发布确认弹窗

## B. 详情内容区组件
- B1. 返回学科列表按钮
- B2. 搜索知识点输入框
- B3. 顶部操作按钮区：编辑知识树、删除、导出知识树
- B4. 左侧知识树结构区
- B5. 右侧知识点详情区

# 交互逻辑

## 1. 已设置定时发布后的默认展示
1.1、当用户完成定时发布设置后，返回详情页顶部展示蓝色定时发布提醒条  
1.2、蓝色提醒条文案示例：  
【v1.1 版本将于您设定的时间（2026-03-28 02:00）自动发布，发布后更新的内容将正式生效】  
1.3、蓝色提醒条右侧展示【取消定时】按钮  

## 2. 点击取消定时
2.1、用户点击【取消定时】后，取消当前已设置的定时发布任务  
2.2、取消成功后，蓝色定时发布提醒条消失  
2.3、页面状态恢复为当前实际待发布状态或普通已发布状态  

## 3. 进入编辑态
3.1、当页面存在蓝色定时发布提醒条时，用户仍可继续点击【编辑知识树】进入编辑态  
3.2、进入编辑态后，顶部蓝色定时发布提醒条隐藏  
3.3、编辑过程中不展示蓝色定时发布提醒条，避免与当前编辑状态冲突  

## 4. 完成编辑且无变更
4.1、用户点击【完成编辑】后，系统自动比对本次编辑前后内容  
4.2、若本次编辑未产生实际变更，则页面顶部继续展示原蓝色定时发布提醒条  
4.3、原有定时发布任务保持不变  

## 5. 完成编辑且产生新变更
5.1、用户点击【完成编辑】后，若系统识别到本次编辑产生了新的变更，则页面顶部不再展示蓝色定时发布提醒条  
5.2、顶部改为展示橙色待发布提醒条  
5.3、橙色提醒条用于提示：当前存在新的待发布内容，需要重新确认发布  
5.4、橙色提醒条右侧展示【发布】按钮  

## 6. 再次点击发布
6.1、用户点击橙色待发布提醒条中的【发布】按钮后，打开发布确认弹窗  
6.2、弹窗中需回写上一次填写过的发布说明内容  
6.3、弹窗中的本次变更列表需更新为：
- 上一次定时发布任务中已记录但尚未正式生效的变更内容
- 本次重新编辑后新增的变更内容
6.4、系统需将上述两部分内容合并回显，作为当前重新确认发布时的完整变更说明依据  

# 业务规则

## 一、顶部状态展示规则
1. 当存在有效的定时发布任务，且当前未产生新的待发布变更时，顶部展示蓝色定时发布提醒条  
2. 当存在有效的定时发布任务，但用户再次编辑并产生新的待发布变更时，顶部展示橙色待发布提醒条  
3. 蓝色和橙色状态提醒条不可同时展示  
4. 编辑态下，顶部蓝色定时发布提醒条隐藏  

## 二、编辑后状态切换规则
1. 用户在定时发布未执行前，可以再次进入编辑态修改内容  
2. 若点击【完成编辑】后无实际变更，则维持原定时发布状态，顶部继续显示蓝色提醒条  
3. 若点击【完成编辑】后产生实际变更，则原定时发布提示不再直接展示，顶部切换为橙色待发布提醒条  
4. 该切换的本质是：原定时发布信息已不足以覆盖当前最新待发布内容，需要重新确认发布  

## 三、发布确认弹窗回写规则
1. 当用户在已存在定时发布任务的基础上，再次产生新的待发布变更并点击【发布】时，发布确认弹窗需回写上一次填写过的发布说明  
2. 回写内容为上一次用户在发布确认弹窗中填写并已保存的发布说明内容  
3. 若上一次发布说明为空，则按空值处理，不强行生成默认文案  

## 四、变更说明合并回显规则
1. 当用户再次点击【发布】进入发布确认弹窗时，系统需更新本次变更列表  
2. 变更列表需合并展示：
- 上一次定时发布任务对应的待生效变更
- 本次重新编辑后新增的待发布变更
3. 合并后的变更列表作为当前重新确认发布的完整变更范围  
4. 不允许仅展示本次新增编辑内容，而遗漏上一次尚未生效的定时发布内容  

## 五、定时发布任务规则
1. 设置定时发布后，在正式生效前，该定时发布任务始终存在  
2. 若用户未产生新的变更，则原定时发布任务继续有效  
3. 若用户产生新的变更并重新确认发布，则后续发布内容以重新确认后的发布任务为准  
4. 若用户主动取消定时发布，则当前定时发布任务失效  

## 六、权限规则
1. 仅教研主管可取消定时发布  
2. 仅教研主管可在橙色待发布条中点击【发布】重新发起发布确认  
3. 教研员仅可查看状态信息，不可执行取消定时或重新发布操作  

# 状态与异常

## 页面状态
- 定时发布中状态：展示蓝色定时发布提醒条
- 再编辑中状态：编辑态下隐藏蓝色定时发布提醒条
- 再编辑无变更状态：退出编辑后恢复蓝色定时发布提醒条
- 再编辑有变更状态：退出编辑后展示橙色待发布提醒条
- 取消定时后状态：移除蓝色提醒条，恢复实际页面状态

## 异常与边界
- 若用户进入编辑态但未产生任何实际变更，顶部仍应保持原定时发布状态
- 若用户产生变更但未重新点击发布确认，则顶部持续显示橙色待发布提醒条
- 若原定时发布任务存在，且本次变更列表合并失败，则不允许直接进入新的发布确认流程，应提示系统异常
- 若取消定时失败，则保留当前蓝色提醒条，并提示失败原因

# 数据来源

| 数据名称 | 来源 | 用途 |
|----------|------|------|
| 当前定时发布任务信息 | 页面状态 / 发布任务数据 | 展示蓝色定时发布提醒条 |
| 上一次发布说明 | 上一次定时发布任务记录 | 回写到发布确认弹窗 |
| 上一次待生效变更列表 | 上一次定时发布任务记录 | 合并展示到新的发布确认弹窗 |
| 本次新产生的变更列表 | 当前编辑结果对比数据 | 生成橙色待发布提醒条及更新发布确认弹窗内容 |
| 当前用户角色 | 登录用户信息 | 控制取消定时和重新发布按钮权限 |

# 技术要求

- 顶部状态条需支持蓝色定时发布态与橙色待发布态的切换展示
- 编辑态下需隐藏蓝色定时发布提醒条
- 完成编辑后需支持自动判断是否存在实际变更
- 若存在新变更，需将历史待生效变更与本次新增变更合并后回显到发布确认弹窗
- 若无新变更，需恢复展示原蓝色定时发布提醒条
