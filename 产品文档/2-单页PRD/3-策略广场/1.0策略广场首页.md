# 1.0 策略广场首页【GPT更新】

# 页面目标
用于集中展示和管理自适应学习系统的策略配置模块首页。  
用户可在首页查看当前已开放的策略模块入口、模块状态、功能简介，并进入对应模块进行管理。

> 说明：
> - 本页面为策略配置总入口页。
> - 页面顶部**不展示面包屑**。
> - 本期仅开放部分模块，未开发模块仅做占位展示，不支持进入实际配置详情。

# 交互逻辑

## 1. 进入策略广场首页
1.1、用户进入策略广场首页  
1.2、系统展示页面标题与说明  
1.3、系统按分组展示策略模块卡片  
1.4、页面顶部不显示面包屑导航

## 2. 查看出题策略模块
2.1、用户查看【出题策略】分组  
2.2、系统展示 3 张策略卡片：
- 学情诊断
- 单知识点出题
- 模拟考

2.3、其中：
- 学情诊断为本期实际开发模块
- 单知识点出题、模拟考为本期占位模块

## 3. 查看基础配置模块
3.1、用户查看【基础配置】分组  
3.2、系统展示本期范围内的基础配置模块  
3.3、其中：
- 掌握程度划分为本期实际开发模块
- 追根溯源不在本期范围

## 4. 点击已开放模块
4.1、用户点击本期已开放模块卡片  
4.2、系统跳转至对应详情管理页面  
4.3、本期允许进入的模块包括：
- 学情诊断
- 掌握程度划分

## 5. 点击占位模块
5.1、用户点击本期仅占位展示的模块卡片  
5.2、系统不进入正式详情页  
5.3、建议处理方式二选一：
- 方案A：卡片整体不可点击，并显示【敬请期待】/【暂未开放】
- 方案B：点击后提示【该模块暂未开放】

> 从方案设计角度，建议优先采用**方案A：直接不可点击**，更干净，也更符合“仅占位展示”的产品语义。

## 6. 悬停卡片
6.1、用户鼠标悬停在策略卡片上  
6.2、卡片可展示轻微悬停反馈，如阴影增强、边框高亮  
6.3、仅已开放模块可体现“可进入”的交互暗示  
6.4、占位模块不建议做过强的可点击悬停反馈，以避免误导用户

# 业务规则

## 一、页面结构规则
1. 首页用于展示策略模块总入口。  
2. 页面顶部不显示面包屑。  
3. 首页按模块分组展示策略入口。  

## 二、本期模块范围规则
1. 【出题策略】分组本期仅开发：
- 学情诊断

2. 【出题策略】分组本期仅占位展示：
- 单知识点出题
- 模拟考

3. 【基础配置】分组本期仅开发：
- 掌握程度划分

4. 【基础配置】分组中：
- 追根溯源不在本期范围

## 三、模块状态展示规则
1. 已开发并可管理的模块，展示真实状态信息，如：
- 已发布
- 待发布 · X项变更

2. 本期仅占位的模块，不展示真实业务版本流转信息，建议展示为以下之一：
- 暂未开放
- 敬请期待
- 开发中

3. 占位模块不应给用户造成“当前可配置、可发布”的误解。

## 四、进入权限规则
1. 本期开放模块可点击进入管理页。  
2. 本期未开放模块不可进入真实管理页。  
3. 若后续模块上线，仅需将其状态从占位切换为可进入。  

## 五、首页展示口径规则
1. 首页展示的是模块入口概览，不承载具体策略配置内容。  
2. 首页应优先体现：
- 当前有哪些策略模块
- 哪些模块已开放
- 哪些模块仅占位
- 哪些模块有待发布状态

# 状态与异常

## 页面状态
- 正常状态：展示策略模块入口
- 占位状态：部分模块仅展示，不可进入
- 待发布状态：已开发模块存在未发布变更
- 已发布状态：已开发模块当前为已发布版本

## 异常与边界
1. 若某占位模块被误配置了跳转地址，前端仍应拦截，避免进入空白页。  
2. 若模块暂无状态数据，已开放模块可显示默认状态，占位模块则显示【暂未开放】。  
3. 若后端暂未提供动态接口，首页可先使用前端配置数据渲染，但需保留后续接口化能力。

# 技术要求

1. 页面顶部不显示面包屑。  
2. 首页模块展示需支持“可进入”和“仅占位”两种状态。  
3. 占位模块需在视觉和交互上与已开放模块区分明确。  
4. 首页模块分组结构需支持后续扩展，避免后续新增模块时改动过大。  
5. 已开放模块的状态、版本号建议支持接口动态获取。  
6. 未开放模块建议通过统一字段控制，例如：
- `isAvailable`
- `isPlaceholder`
- `comingSoonText`
