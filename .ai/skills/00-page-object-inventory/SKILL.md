# 页面对象清单 Skill（Skill0）

## 目标

在 Skill1 深度审核之前，先锁定「审什么」：

- 全页模式：盘点页面业务对象，标注必审 / 可跳过 / 待你定
- **增量模式**：只将 **直接变更 A ∪ 连带影响 B** 标为必审；与本次无关的 C 标可跳过，**不**整页重审

**本 Skill 只锁「审什么」，不定「怎么定」。**

明确不做：

- 不出 `1A2C3D` 决策题
- 不写完整业务逻辑 / PRD / 需求注册表
- 不把每个可见装饰元素都当成必审对象
- 不直接改页面代码

执行前必须先读：

```txt
.ai/skills/shared/project-context.md
.ai/skills/shared/incremental-scope-mode.md
```

## 在整体流程中的位置

```txt
定模式/范围/前提 → Skill0 出清单并经用户确认 → Skill1 只审「必审」→ Skill2 …
```

- Skill0 **必须在 Skill1 之前**完成并得到用户确认。
- Skill1 不得对清单外对象擅自开审；用户补漏后，先回 Skill0 更新清单，再进 Skill1。
- Skill2 及之后仍以 Skill1 决策记录为准；本 Skill 不替代决策。

## 模式选择（必须先定）

1. 读取用户表述与 `incremental-scope-mode.md`，判定 **全页** 或 **增量**。
2. 若用户说「本次只改… / 局部 / 后置补需求 / 不要整页审」，启用 **增量模式**。
3. 用一句话复述：模式 + 页面范围 + 变更摘要（增量时），再扫对象。

## 必须遵循的流程

1. 确认页面/流程范围（名称、路由、主要文件）。未知则先问，不要扫全站。
2. 确认前提（目标用户、本期不做、重点方向）。无额外前提可回复「无额外前提」。
3. **增量模式额外确认**：本次变更摘要（改了什么能力/字段/模块）。未知则先问。
4. 按 `project-context.md` 的读码约定打开相关文件（含隐藏态：Tab、弹窗、抽屉、空状态）。
5. 扫出候选对象并给处置：
   - 全页：`必审` / `可跳过` / `待你定`
   - 增量：必须标 **影响类型 A/B/C**，且 A、B → 必审，C → 可跳过（待你定仅用于拿不准是否连带）
6. 按「首次输出格式」交用户核对。
7. 用户确认后写入清单文件；增量模式建议同时写入或更新 `docs/prd-workflow/change-scopes/<批次>.scope.md`（若用户需要）。
8. 告知：下一步 Skill1 **只审必审（增量下即 A∪B）**。

## 增量模式：连带分析（必须做）

对每个 **A**，按 `incremental-scope-mode.md` 第 3 节追问展示 / 编辑 / 保存提交 / 校验 / 导入导出 / 状态权限等，将命中对象列入 **B**。

- **禁止**未做连带分析就把「本页其余按钮」批量标为 C。
- **允许**将确认无耦合的区域合并为一行 C：「其余未受影响区域」，备注说明已排查。
- **B 必须逐条列出**（例如页面级保存、导入校验、导出列），不可吞进「其余」。

## 候选对象扫描清单（通用类型）

有则列入，无则跳过该类：

| 类型 | 示例（通用） |
| --- | --- |
| 标题/范围文案 | 页面标题、当前对象名称 |
| Tab / 维度切换 | 内容 Tab、筛选维度 |
| 字段/表单项 | 新增或修改的业务字段 |
| 数量/统计 | 角标、计数 |
| 辅助说明文案 | hint、顶部说明、Excel 顶行说明 |
| 状态标识 | 发布态、未设置、空态 |
| 列表/卡片/表格区域 | 列表项、卡片、空状态区 |
| 操作按钮 | 保存、取消、发布、导入、导出、删除 |
| 筛选/抽屉/弹窗 | 选择器、确认框、导入结果 |
| 导入/导出产物 | 模板列、校验规则、说明文案 |

扫描原则：

- 以用户能感知的**业务对象**为单位，不拆纯装饰。
- 同一决策单元可合并；规则明显不同则分行。
- 隐藏态也要扫。
- 增量模式下：先列 A，再推 B，最后收 C；不要先全页铺开再假装增量。

## 建议处置口径

| 处置 | 含义 |
| --- | --- |
| 必审 | 进 Skill1；增量下 = A 或 B |
| 可跳过 | 不进 Skill1；增量下 = C，或明确无业务分歧的装饰 |
| 待你定 | 拿不准是否该审 / 是否连带；默认确认清单时升为必审，除非用户指定跳过 |

## 首次输出格式

### 全页模式

```md
一、页面名称
<页面名称>（<路由或主要文件>）

二、审核模式
全页

三、前提与范围
- 前提：<…>
- 本期明确不审/不做：<如有>

四、对象清单（请对着页面核对）

| 序号 | 对象 | 类型 | 页面位置 | 建议处置 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 1 | … | … | … | 必审 / 可跳过 / 待你定 | … |

五、请你确认
- `确认清单`
- `确认清单；补充：…为必审`
- `确认清单；3改为可跳过；5改为必审`
- `还有遗漏：…`
```

### 增量模式

```md
一、页面名称
<页面名称>（<路由或主要文件>）

二、审核模式
增量

三、前提与变更摘要
- 前提：<…>
- 本次变更摘要：<用户要改的能力/字段/模块>
- 约束：仅对 A∪B 审核与编写业务逻辑；不对 C 重审或改写既有口径

四、对象清单（请核对 A/B 是否漏连带）

| 序号 | 对象 | 类型 | 影响类型 | 页面位置 | 建议处置 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | … | 字段 | A 直接变更 | … | 必审 | … |
| 2 | … | 按钮 | B 连带影响 | … | 必审 | 保存时需带上新字段 |
| 3 | 其余未受影响区域 | 区域 | C 无影响 | … | 可跳过 | 已排查与本次变更无耦合 |

五、连带自检（可选，≤5 条）
- 是否已覆盖：展示 / 编辑 / 保存提交 / 校验 / 导入导出 / 状态权限

六、请你确认
- `确认清单`
- `确认清单；补充 B：保存校验、导出说明为必审`
- `还有遗漏：…`
```

## 用户确认与修订

1. 补漏 / 改处置 / 改 A·B·C 后，再请确认。
2. 确认时未改的「待你定」默认升为 **必审**。
3. 确认前不写清单文件，不开始 Skill1。

## 清单文件

```txt
docs/prd-workflow/inventories/<页面或流程>.inventory.md
```

增量模式结构示例：

```md
# <页面名称> 对象清单

## 页面范围
- 页面/流程：
- 路由：
- 相关代码文件：
- 前提：
- 审核模式：增量
- 本次变更摘要：

## 清单状态
- 状态：已确认
- 确认说明：

## 必审对象（A∪B）
1. <对象> — <A|B> — <类型> — <位置> — <备注>
2. …

## 可跳过对象（C）
1. <对象> — <原因>
2. …

## 供 Skill1 使用的约束
- 只对「必审对象」输出待确认问题。
- 增量模式下不对 C 重审或提出改写既有口径的建议。
- 发现新的连带对象：先回 Skill0 补清单并确认，再继续 Skill1。
```

## 与 Skill1 的衔接门禁

无已确认清单时：说明需先做 Skill0，询问是否现在开始；**不要**直接输出大批决策题。

## 输出约束

- 面向用户：短、可对照勾选。
- 使用页面上的具体对象名。
- 除必要路径外用中文。
- 业务示例子不要写死成唯一业务域；以当前 `project-context.md` 与用户给定页面为准。
- 通用规则以 `incremental-scope-mode.md` 为准，本 Skill 不写死某次需求字段名。
