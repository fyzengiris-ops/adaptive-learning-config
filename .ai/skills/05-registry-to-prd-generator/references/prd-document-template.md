# 页面级 PRD 文档模板

生成页面级 Markdown PRD 时，使用下面结构。

业务逻辑章节必须原样来自 `logicSections`，不要强制写成「显示说明 + 操作说明」。

## 模板

```md
# <页面名称> PRD

## 1. 页面范围

### 1.1 当前页面
- 页面名称：
- 所属模块：
- 页面路由/视图：
- 相关代码文件：

### 1.2 上级页面/上游入口
- 上级页面：
- 入口位置：
- 进入方式：
- 传入数据：
- 依赖状态：

### 1.3 下级页面/下游流程
- 下级页面/下游流程：
- 触发方式：
- 传出数据：
- 后续状态：
- 返回逻辑：

### 1.4 范围边界摘要
- 本文档覆盖：
- 本文档不覆盖：

## 2. 功能概述

<简述页面解决什么问题、服务什么场景、当前文档覆盖哪些能力。>

## 3. 业务逻辑说明

### <需求编号> <需求标题>

来源：<代码事实 / 确认决策 / 代码事实 + 确认决策>

#### <logicSection.title>
1.1 <item>
1.2 <item>

#### <logicSection.title>
1.1 <item>

#### 验收标准
1. ...

## 4. 范围边界

### 4.1 本文档覆盖

- ...

### 4.2 本文档不覆盖

- ...

## 5. 验收标准

### <需求编号>

1. ...

## 6. 来源追溯

- 需求注册表：
- 来源决策文件：
- 相关代码文件：
```

## 业务逻辑填写规则

- 遍历 `requirement.logicSections`
- 每个 section 输出一个 `#### title`
- `items` 使用单层 `1.1`、`1.2` 编号
- 有几个 section 写几个；没有操作类规则就不要硬写操作说明
- 忽略旧 `display` / `operation` 字段

## 上游/下游填写规则

### 当前页面

读取：`pageName`、`module`、`route`、`relatedFiles`

### 上级页面/上游入口

- 当前视图从哪个 hash / 入口进入
- 上游通过什么按钮、Tab、弹窗打开
- 依赖哪些上下文状态

### 下级页面/下游流程

优先从 `logicSections` 与代码事件判断：

- 点击哪个入口触发下游
- 是否打开弹窗/抽屉、切换 hash、切 Tab/步骤
- 是否写入收藏或传出数据

无明确下游时写“未在当前代码或注册表中确认明确下游流程”。

## 过滤规则

默认过滤空兜底：

- 无额外权限限制
- 无额外数据流转
- 无异常场景
- 本对象无操作入口
- 本对象仅展示
- 空字符串
- 空数组

## sourceType 中文映射

- `code`：代码事实
- `decision`：确认决策
- `code+decision`：代码事实 + 确认决策
